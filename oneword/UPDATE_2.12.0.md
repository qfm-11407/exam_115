# OneWord 2.12.0：縮短交卷後的評分等待

這次保留 2.11.0 已通過的收件紀錄、原圖鎖定、自動重傳與上傳優先，調整圖片保存後的評分排程。預設同時判讀仍為 2 份，不需要更改金鑰、模型或部署網址。

## 改了什麼

- 教師端改用批次評分請求。GAS 依設定一次保留 1～3 份工作，在共用鎖外使用 `UrlFetchApp.fetchAll` 發出各自獨立的 AI 請求，再一次寫回該批結果。每位學生仍有獨立圖片與判定。
- GAS 每批完成就保存結果並接續下一批，不必每份回瀏覽器再排下一份。一個請求最多啟動 28 批，並在每批開始前檢查 45 秒工作預算；到達預算後由教師頁接續。這不是保證請求在 45 秒內結束，單次外部服務等待仍可能較久。
- 學生端保存圖片後只確認交卷，不再各自發出一次評分請求，減少同時交卷後的額外 GAS 流量。教師頁保持開啟以處理評分和自動換題。
- 上傳中仍會讓新評分工作等待，並在批次取件鎖內再次檢查，保留多人壓線交卷的保護。
- 兩台教師端及舊學生頁發出的評分共用同一個同時判讀上限；每份工作仍有識別碼，舊工作不能覆蓋新結果。
- 只有辨識不明的該份答案會再呼叫一次 AI；同批其他已確定答案不會一起重判。服務錯誤保留為未計分的可重試狀態。
- 前端依後端 `batchJudging` 能力切換；先更新網頁、尚未更新 GAS 時仍使用舊評分流程。新後端也保留舊評分介面供舊頁面相容。

## 已驗證的範圍

使用實際後端程式搭配模擬服務，單題 28 人、同時 2 份、只計教師發起的評分階段：

| 操作 | 原流程 | 批次流程 |
|---|---:|---:|
| 教師評分請求 | 28 | 1 |
| 房間狀態提交 | 56 | 28 |
| 取得共用鎖 | 56 | 28 |
| AI 請求／判讀完成 | 28／28 | 28／28 |

這是操作次數比較，不是實際 GAS 耗時；不包含上傳、一般輪詢和舊學生頁請求。45 秒預算、服務耗時及其他裝置操作可能使正式環境需要多次教師評分請求。開發專案可執行 `node oneword/scripts/profile-judging.mjs` 重現計數。

回歸測試涵蓋批次上限、混用舊工作、教師併發、部分 API 失敗、只重判不明答案、取消後不再啟動下一批、逾時接續、結果保密及計分不重複。真實加速幅度仍需更新部署後測量，不能把操作數減半當成時間減半。

## 更新步驟

1. 結束目前測驗；保留原本 `.local` 測試資料夾。
2. 解壓 `oneword-v2.12.0.zip`。將網頁檔案覆蓋 GitHub 的 `oneword/`，可直接使用整包內容；ZIP 本身不能當網頁執行。
3. 原 GAS 專案覆蓋 `gas/Code.gs` 的內容到「程式碼」，覆蓋 `gas/Student.html` 的內容到「Student」HTML。Bridge 與 manifest 沒有功能變更，整包覆蓋也可以。
4. GAS「部署 → 管理部署作業 → 編輯 → 新版本 → 部署」。沿用原部署，不要另建網址，也不要重新執行 `setup_`。
5. 教師與學生重新開啟頁面。教師應顯示「網頁 v2.12.0 · GAS 2.12.0」，學生顯示「平板模式 v2.12.0」。只有更新 GitHub 不會啟用批次評分。

## 用相同壓線條件重測實際 AI

在解壓後的測試資料夾執行：

```bat
TEST_GAS_AI_28.cmd --seconds 30 --send-at 29 --timeout 180
```

會實際存圖並使用 GAS 既有的 API 金鑰評分，產生 API 費用。測試工具 v1.3.1 摘要應顯示 `backendVersion: "2.12.0"`、`judgingEngine: "gas-batch"`。詳細步驟見 [LOAD_TEST_AI.md](LOAD_TEST_AI.md)。

比較 `sendToAllAiJudged`、`remainingAiWaitAfterUploads` 與 `sendToRevealed`；同時確認圖片和判讀均為 28 份成功。先前 2.11.0 的 AI 測試是 180 秒作答提早送出，不能與 30 秒第 29 秒送出的數據視為完全相同條件。

測試工具會實際按公布與下一題，驗證第一題的 AI、結果畫面與第二題可作答；仍不是整場自動連跑多題的壓測。測試固定寫「木」，不以答對率驗證學生真實筆跡的辨識準確率。

## 仍然存在的限制

教師頁關閉、休眠或失去登入時，後續排程可能停住。API 錯誤仍需教師重試；辨識不明的自動公布規則本次未改。第一次請求超過傳送緩衝才到 GAS，仍不能靠本次評分加速補成有效交卷。

Google 官方參考：[fetchAll](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app)、[減少服務呼叫及批次操作](https://developers.google.com/apps-script/guides/support/best-practices)。
