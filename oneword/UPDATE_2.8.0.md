# OneWord 2.8.0 更新

減少判讀工作之間的空檔、重複圖片傳輸及房間摘要讀寫，並提供教師速度紀錄。

## 更新步驟

1. 解壓縮 oneword-v2.8.0.zip，把內容覆蓋至 GitHub 原本 oneword/，提交更新。不要直接把 ZIP 當網頁上傳。
2. GAS 原專案的 Code.gs 覆蓋為 gas/Code.gs；Student HTML 覆蓋為 gas/Student.html。Bridge 不變。
3. 「部署 → 管理部署作業 → 原部署 → 編輯 → 新版本 → 部署」。保留原網址，不需重跑 setup_，既有金鑰、登入碼與資料保留。
4. 教師、大螢幕重新整理，學生重新開啟作答頁。教師台確認「網頁 v2.8.0 · GAS 2.8.0」；學生頁確認「平板模式 v2.8.0」。

## 改善內容

- 判讀一份完成後，只要仍有待判讀答案就立即接下一份。空佇列、錯誤、結束測驗或切換題目會停止舊工作；仍維持原本同時份數限制，未提高上限。
- 大螢幕只下載新增答案；同一張圖後端也會快取，避免每次新增交卷都重讀全班圖片。緩衝期間仍拒絕圖片請求。
- 省略內容未改變的房間摘要重寫；每次工作只讀一次模型與同時份數設定。交卷及判讀狀態依舊立即保存到 Drive，寫入前仍讀最新狀態。
- 教師與大螢幕在重要階段加快查詢，平板模式僅在倒數末段與緩衝期間稍微加快；查詢等待上一個回應完成才接續，避免重疊。
- 教師台「本場 API 使用量」下方新增「本題速度紀錄」。受理等候為 GAS 開始處理至取得交卷預約的時間；圖片保存包含預約保存及 Drive 存圖；等待判讀從存圖完成到啟動工作；AI 判讀為實際 API 請求時間（不明確時包含第二次）；總時間從 GAS 收到送出請求到完成判讀，部分保存作業可能尚未計入。各欄位依有紀錄的答案分別取平均，並列樣本數。

速度紀錄只供教師查看，不包含學生裝置到 GAS 的網路時間；流程演練沒有真正 AI 請求，AI 耗時會是 0。舊題目沒有計時資料的欄位顯示「尚無紀錄」。

## 驗證

測試涵蓋連續接件、同時份數上限、空佇列停止、切換房間／舊題防護、圖片增量與快取、同數量名單更換、重疊圖片請求共用、摘要寫入減量、速度紀錄保密、同步頻率，以及既有白名單／計分／5 秒緩衝。

未在真實校內網路進行 25 台裝置速度比較，實際等待仍受 GAS、Drive、AI 與網路影響，不能保證特定加速倍數。
