# OneWord 2.10.1：交卷自動重試及多人測試

## 更新方式

1. 將 `github-upload/` 內容覆蓋 GitHub 的 `oneword/`。
2. 將原 GAS 專案的 `Code.gs`、`Student` HTML 分別覆蓋為 `gas/Code.gs`、`gas/Student.html`。Bridge 不變。
3. 在原部署選「管理部署作業 → 編輯 → 新版本 → 部署」。不要重跑 setup_。
4. 教師及學生重新開啟頁面，確認教師顯示「網頁 v2.10.1 · GAS 2.10.1」，平板頁顯示 v2.10.1。

固定後端網址、原房間、金鑰與成績保留。只更新 GitHub 不會更新 GAS 的平板介面。

## 修正

- 暫時忙碌、網路或服務失敗時，以約 1.5～13 秒逐步退避並加入隨機間隔，自動重送同一張已鎖定圖片。每個頁面只維持一個送出程序與一個重試計時器；也可手動重送。
- 重新開啟同一題時會讀取本機待傳圖片並重試。正式截止、身分失效等不可重試錯誤會停止自動重試並顯示原因，不會顯示成功。
- 已收到保存成功回覆後，舊輪詢結果不會將畫面倒退成未繳交。換題、移除學生或結束時取消舊題重試，舊回覆不能鎖住新題。
- Drive 已建立圖片但回覆遺失時，重試會在該題資料夾核對同學號圖片的完整內容，復用相同圖片；查找與讀圖均不持有共用鎖。既有重複檔案不會被刪除。
- 首次請求在伺服器收件期限前已進入 submit_、但等待鎖到逾時的，以伺服器記錄的進入時間判定；真正首次抵達已逾期、或教師已手動收卷者仍拒收。已保留交卷紀錄的同圖重試可在期限後恢復。

此修正不代表解決所有 GAS 容量限制。若首次請求因服務限制根本沒有執行，後續才首次抵達且超過寬限，仍可能拒收；須用真實測試確認校內網路、部署與 Drive 情況。

## 測試範圍

本機模擬啟動 28 個獨立學生控制器、一個教師及一個大螢幕控制器。28 個送出處理器同一批啟動，刻意只讓前 4 人第一次成功，其餘各收到兩次忙碌回應，另注入回覆遺失及 Drive 建檔後中斷。

原版等待 60 秒虛擬時間仍只有 4／28 完成；修正版可完成 28／28、28 份存圖紀錄，且沒有重複圖。這是程式流程測試：沒有真實 Google 連線、Drive 上傳或 AI 呼叫；虛擬完成時間不是速度實測，不能拿來推算每題耗時。

真實瀏覽器工具及操作方法見 [LOAD_TEST.md](LOAD_TEST.md)。真實 GAS／Drive、AI 評分速度、不同裝置與校內 Wi-Fi 均仍需實測。
